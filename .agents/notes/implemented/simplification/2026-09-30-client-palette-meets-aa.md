# Agent Note: 面板配色以 WCAG AA 为准，并由测试从产物 CSS 读取

Status: implemented

## Problem

卡片自成一体的白底配一套浅灰文字。按 WCAG 2.1 相对亮度公式实算，26 条文本色规则中**无一达到 4.5:1**：次级文字全部用 `#86868B`（3.62:1），三处徽章在同色 10% 底上分别是 2.99–4.35:1，计数与图例更小。标题 `#1D1D1F`（16.83:1）说明作者在意可读性，但次级层是整体选偏而非个别遗漏。

受影响的恰恰是信息密度最高、最需要被读到的部分：探测轮次的结论行、每行失败原因、底部徽章图例。

另外，开关是真原生 checkbox，被 `opacity:0;width:0;height:0` 隐藏，浏览器默认焦点环随之消失，而 CSS 里**没有任何** `:focus` / `:focus-visible` 规则——键盘用户 Tab 到某一行时画面完全无变化。

## Decision

- 全部 26 条文本色压深到 ≥4.5:1（次级文字统一 `#6B6B72`，徽章各自压深）。开关轨道是非文本指示，保留原样 + 边框与阴影。
- 补 `:focus-visible + .opf-track` 外环与 `:focus-within` 行背景。
- 新增测试 `every palette colour meets WCAG AA against the card`，**从 `src/client.js` 读出 CSS** 再解析，而不是在测试里重抄一份调色板。

## Alternatives considered

- **只修探测相关的那几处**。论据是次级文字的 3.62:1 属于"勉强可读"，改与不改观感差异小。否决：结论行恰恰是失败时用户唯一要看的东西，而它的对比度最低。
- **换成整套深色主题以绕开对比度**。否决：这是宿主主题的跟随式卡片，深色会与宿主割裂；且改动面远大于问题。
- **在测试里维护一份调色板副本**。论据是不必解析 CSS 字符串。否决：那样测试守住的是自己的副本，产物改了它不会红——与本次要修的正是同一类"测试不测产物"。

## Consequences

- **收益**：26/26 达标（实算复核通过），键盘用户有可见焦点；配色回归由测试拦截。
- **代价与已知上限**：测试用正则解析 CSS，只能覆盖形如 `color:#RRGGBB` 的写法；将来若改用 CSS 变量或 `color-mix()`，这条断言会**静默地一条都匹配不到**。已在测试里加了 `rules.length > 20` 的前置断言，规则数骤减时立刻失败，而不是伪装成"全部通过"。
