# Agent Note: 探测的结论必须能推翻它自己的前提——沉默、进度与通道

Status: implemented

## Problem

上游审阅者在真实 DSH `0.2.0-rc.2` 上跑完本 PR 后提了四条缺陷加一条 UI 跟进，全部复现。五条里有四条落在同一个主题上：**探测轮的结论没有被用来修正探测所依赖的前提**。

1. **一条沉默的通道可以永久移除模型。** `strength()` 给 `dead`=2、其余=1，所以「通道 A 404 + 通道 B ECONNRESET」的最终结论是 `dead`，`catalog.ts` 据此写 `swept: true` 成为终局。但一次**没有跑完**的请求根本没说这个模型任何事，而 404 恰恰是「走错通道」的标准长相。目录自己的注释写着「先问完所有通道再下结论」，代码问完之后却把「没问到」当成了「问过了」。

2. **探测赢下的通道被丢掉了。** `probeModel` 在备用通道成功时直接返回该 outcome，可持久化的只有 `{verdict, at, reason, swept}`——**赢的通道没有落盘**。模型记录的 api 仍由 `channelFor` 推断，于是探测报 ok、对话继续打 404。这不是 bug，是这条链路的另一半从来就没写。

3. **目录刷新会覆盖正在跑的轮次。** `adopt()` 无条件用持久化报告替换 `state.probeRun`，而 `sync()` 的 200 分支也调 `adopt`。这是 0.3.2 那个「报告重启后仍在」修复引入的回归：活跃轮被换成旧报告，正在跑的轮次继续在被换掉的对象上累加 `done`，于是面板报 4/2。304 分支不调 `adopt`，所以只走 304 的测试永远看不到。

4. **HTTP 清理会拆掉别人的包装。** disposer 无条件写回 original，不检查当前值还是不是自己的 wrapper。fetch 那条路径一直有这个归属检查，两条路径没对齐。

5. **详情页在自动轮次结束后不重读。** `loadCatalog()` 只对「点击等待过」的那轮执行，于是自动轮次结束后页面留着 1970 时间戳和过期的「未测到」文案，直到重新打开页面。

## Decision

- **沉默是否决，不是输掉一场比较。** 重写 `probeModel`：任何一条通道给出非 `dead`/非 caller-scoped 的结论就整体返回 inconclusive，并保留它的 reason 与 status——面板需要知道「为什么测不出来」。`strength()` 整个删除：新的规则下只有 `dead` 会被暂存，它不再有比较的对象。
- **通道写入探针记录，由一个函数应用。** `ProbeResult`/`ProbeOutcome` 的 `ok` 带上 `api`，`ProbeRecord` 新增可选 `api`，`applyMeasuredChannel()` 是唯一施加它的地方，两个调用方：轮次记录时、热读采纳时（后者才是「跨重启」的那一半）。只接受两个已知通道，读缓存时校验。
- **报告恢复收敛到启动。** `adopt()` 增加 `restoreRound` 参数，热读传 `true`，`sync()` 不传。刷新更新目录与结论，对进行中的轮次无话可说。
- **disposer 先验明正身再写回。** 记录自己装的 wrapper，只有当前值仍等于它才还原。附带修好了重载顺序：旧 patch 的 disposer 原本会剥掉新 patch 的 wrapper。
- **UI 用 `followed` 而不是 `awaiting`。** 「这一轮是我看着跑完的」与「这份报告开页面时就在磁盘上」必须分开，否则每次开页面都要多打一次请求。

## Alternatives considered

- **给沉默降权而不是否决**（例如 `dead` 权重更高但非终局）——否决。`swept` 的语义是终局，任何「可能是 dead」的中间态都会在某一天被写成 `swept: true`，等于把问题推迟。
- **超时不算沉默，只有传输失败算**——否决。上游给的正是超时这一例，而且理由成立：15 秒没回来与「不存在」不是同一件事。
- **探测只记 ok 的通道，不记 dead 的**——这正是采纳的做法。拒绝只说明**这条**通道不行，不说明别的会行；记下来会把对话导向刚被证明失败的那条。
- **刷新时若轮次在跑就整体跳过 adopt**——否决。刷新该更新的模型和结论还是要更新，只是不能碰 `probeRun`。把闸门开在那一段而不是整个函数上。

## Consequences

- `dead` 现在要求**每一条被问的通道都完成了**。代价：一条常年超时的通道会让模型永远停在列表里而不是被移除——这是保守方向，也是「坏窗口的代价是一行灰字，不是一个模型」这条既有承诺的直接推论。
- 探针记录多一个可选字段，schema 版本不变（可选字段向后兼容，旧文件读出来没有它）。
- 模型可能被重新指向另一条通道。这是被观测到的答案，不是推断——正是这个修复存在的理由。
- 五条各有守护测，且**逐条做过变异验证**：把修复改回去，对应测试必须失败。第一条、四条、UI 一条、#3、#2 的两个半边都单独验过。
